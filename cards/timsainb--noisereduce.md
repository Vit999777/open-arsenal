# noisereduce — проверяем очистку речевых вставок

- Исходный проект: https://github.com/timsainb/noisereduce
- Направление VITTORA: музыка — записанные речевые вступления к музыкальным публикациям.
- Дата проверки: 2026-11-02.
- Степень проверки: изучена документация; статус reviewing. Установки, обработки записи VITTORA и измерений не было.
- Публикация: blocked. [Черновик подписи](../posts/2026-11-02_timsainb--noisereduce.md). Telegram message_id, URL и published_at отсутствуют.

## Что делает
Ослабляет фон по частотам: оценивает, какие части звука похожи на шум, и уменьшает их. Есть режим для постоянного фона и режим с меняющимся порогом. Это фильтр, который может затронуть голос; исходное качество не восстанавливается автоматически.

## Польза для VITTORA
Кандидат для записанного голосового вступления к музыкальному тизеру или интервью перед сведением с музыкой. Предполагаемый сценарий: копия шумной записи → пробная обработка → прослушивание редактором → решение о пригодности. Чистую озвучку и мастер песни не обрабатывать без причины. Эффект, экономия времени, качество, охват и доход не измерены.

Текущий процесс, принимаемый за базу сравнения: ручная прослушка, вырезание лишних пауз, уровни/фейды и сведение средствами FFmpeg/редактора. Эти действия сами по себе не удаляют шум внутри реплики. Фактические затраты и параметры конкретной сессии VITTORA пока неизвестны; их записать в пилоте.

## Главное преимущество
Для выбранного варианта NumPy не нужны обученные нейросетевые веса. По сравнению с DeepFilterNet и RNNoise это убирает загрузку модели и отдельный вопрос о её условиях из первого эксперимента. Основание: README и setup.py noisereduce описывают фильтрацию по порогам и обычные численные зависимости; README альтернатив используют готовые модели. Это преимущество прозрачности запуска, а не доказанное превосходство по звучанию.

## Плюсы
- Локальная обработка → исходную запись можно оставить на своём компьютере, без обязательного внешнего API.
- Постоянный и меняющийся порог → можно сравнить два режима на одном фрагменте, не меняя инструмент.
- Параметры функции сохраняются в скрипте → можно повторить настройки. Повторяемость звука на выбранных версиях ещё проверить.

## Запуск
- Сложность: потребуется настройка специалистом, затем работа редактора. Редакционная оценка: Python-функция требует окружения, чтения/записи WAV и проверки параметров.
- Где: локальный CPU-компьютер с Python и совместимыми бинарными пакетами NumPy/SciPy; конкретные ОС, версия Python и машина не выбраны/не проверены. Минимальная версия Python в прочитанном setup.py явно не задана.
- План запуска: в отдельном окружении закрепить проверенный тег и зависимости; заранее подготовить отдельный 60-секундный WAV; передать весь этот файл в reduce_noise с use_torch=False. Два варианта stationary=True/False. Не использовать выбор start_frame/end_frame внутри библиотеки до отдельной проверки PR131. Команды не выполнялись.
- Ресурсы: обязательные GPU, модели, API и хостинг для выбранного пути не нужны. RAM, диск, трафик установки, время CPU, совместимость и срок обработки неизвестны.
- Полная стоимость: лицензия кода — 0; обязательные платные API/модели/хостинг — отсутствуют в выбранном сценарии. Компьютер, электроэнергия, интернет установки, время специалиста, прослушивание/исправления редактора и дальнейшая поддержка остаются расходами. Сумма в рублях не определена, лимит владельцем не назначен; сначала измерить, никаких покупок.
- Лицензия: файл LICENSE — MIT, сохранять copyright и текст условий при распространении. Поле license в setup.py MIT, но classifier упоминает BSD — отмечено расхождение метаданных; распространять только после сверки. Лицензии зависимостей отдельно, полный аудит не сделан. Готовые нейросетевые веса для NumPy-алгоритма не требуются.

## Когда не подходит
Чистый голос, готовая музыкальная фонограмма, клиппинг/перегруз, задачи замены голоса или синхронизации губ. Фильтр способен менять тембр и гармоники; отсутствие шума не доказывает сохранность речи. Для единичной короткой вставки ручной редактор может оказаться проще — сравнить время. Не обещаем пригодность для real-time и длинных мастер-файлов.

## Первый пилот
- Вход: разрешённая копия 60 секунд шумной речевой вставки VITTORA; конкретный файл ещё не выбран. Если есть первые две секунды только фона, сохранить этот образец отдельно.
- Ответственные: специалист готовит окружение и проверяет файлы, редактор VITTORA слушает.
- Действие: отдельно нарезать WAV, сохранить исходник; обработать целый файл в двух режимах NumPy, сохранить версии/параметры. Уровнять громкость сравнительных копий и провести слепую сверку 10 заранее записанных фраз с исходником и текущей ручной обработкой.
- Редакционная цель, не результат: 10/10 фраз без ухудшения разборчивости/новых слышимых артефактов; число аудиоотсчётов строго совпадает, нет NaN и нового клиппинга. Дополнительный ориентир: снижение RMS на одинаковом участке паузы >=3 дБ принимается только при выполнении условия сохранности речи. Это не метрика качества на всём материале.
- Записать peak RAM, время CPU/по часам, время ручной коррекции обоих способов. Результаты пока отсутствуют.
- Лимит ресурсов: один фрагмент, две версии; аппаратный/денежный лимит неизвестен. До расширения эксперимента согласовать фактические потребности по замерам.
- Откат: исходный мастер не изменять; при непрохождении отказаться от результата и продолжить текущий процесс.
