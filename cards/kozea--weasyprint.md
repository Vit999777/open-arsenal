# WeasyPrint — сборка PDF главы из HTML

Направление — книга VITTORA. Проверка документации 03.11.2026, статус reviewing. Запуска и пилота пока не было. [Проект](https://github.com/Kozea/WeasyPrint)

## Применение

Из локального HTML главы получить PDF с полями, колонтитулами, разрывами и навигацией. Печатные стили позволяют повторить оформление после правки текста, а закладки и ссылки помогают читателю ориентироваться. Подходит авторам книг, отчётов и инструкций. [Возможности PDF](https://github.com/Kozea/WeasyPrint/blob/main/docs/api_reference.rst)

## Сравнение

WeasyPrint непосредственно применяет печатные стили HTML/CSS. Pandoc полезен на предыдущем этапе преобразования авторского текста и использует отдельный PDF-движок. wkhtmltopdf также делает PDF из HTML, но его репозиторий архивирован. Текущая база VITTORA — готовый PDF и сайт, точная цепочка их сборки неизвестна.

## Запуск и ограничения

Сложность средняя: требуется подготовить окружение, шрифты и правила печатной вёрстки. В качестве первой среды рассматривается локальный Linux. Конкретный компьютер и версии зависимостей ещё не проверены. Локальный CPU, Python ≥3.11, Pango ≥1.44, зависимости из pyproject.toml и лицензированные шрифты с кириллицей. BSD-3-Clause без лицензионного платежа. Модели, обязательный платный API и хостинг для пилота не требуются. Расходы: рабочее время, вычисления, диск, установка и сопровождение, при необходимости лицензии шрифтов. Суммы и ресурсы неизвестны до замера.

BSD-3-Clause, при распространении сохранить уведомления и условия. Лицензии зависимостей и шрифтов отдельно. Не воспроизводит JavaScript-приложение как браузер. Проверять разрывы, подстановку шрифтов и ссылки. Использовать доверенный HTML с локальными ресурсами, изолировать рендер с запретом сети и лимитами времени/памяти. Условия встраивания шрифтов проверяются отдельно. При наличии только финального PDF понадобится редактируемый текст или HTML главы.

## Первый пилот

Взять разрешённую копию одной главы с заголовками, иллюстрацией и ссылками. Собрать PDF из локального HTML и печатных стилей, сверить с текущим PDF. Цель: 10/10 проверок (три перехода, две закладки, две страницы без обрезки, кириллица, изображение и извлечение текста). Записать время подготовки, рендера и правок, пиковую RAM и размер файла. Пилот не выполнен. Ответственный — редактор с техническим специалистом. Лимит — одна глава в отдельной папке. Денежный и аппаратный потолки ещё не заданы. При отклонении сохранить действующий PDF и ручной процесс.
