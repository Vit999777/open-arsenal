# faster-whisper — сверка озвучки с текстом

- Исходный проект: https://github.com/SYSTRAN/faster-whisper
- Направление VITTORA: book_audio
- Дата проверки: 2026-11-01
- Степень проверки: documentation; не установлен, медиа-пилот не запускался.
- Каталог: reviewing; обзор не означает внедрения.

## Что делает
Преобразует речь из аудио в текст и выдаёт время фраз или слов. Это Python-библиотека: её можно встроить в собственный сценарий обработки, но готового редакционного рабочего места сама по себе она не создаёт.

## Польза для VITTORA
Предполагаемый сценарий: копию 60 секунд готовой русской озвучки аудиокниги VITTORA расшифровать, затем сравнить с согласованным сценарием и найти места для прослушивания. Не заменяет ручную приёмку, не исправляет голос и синхронизацию губ. При уже точном сценарии автоматическая расшифровка может быть лишней.
Текущий процесс — исходный текст плюс ручное прослушивание и сверка при монтаже. WhisperX уже опубликован как кандидат для временных меток, но его обзор не доказывает установленного решения. Фактическая скорость текущего процесса неизвестна.

## Главное преимущество
Перед исходным openai/whisper для Python-пилота: README предлагает CPU int8 и декодирование через PyAV без отдельной системной установки FFmpeg. Это уменьшает число отдельных шагов настройки в таком сценарии; не доказательство экономии времени на VITTORA. В README есть сравнительные замеры авторов на конкретных моделях и оборудовании; их нельзя переносить на нашу русскую запись.

## Плюсы
- Загрузка модели локально и работа на CPU — возможность обработки на своём оборудовании после получения весов.
- Временные метки — возможность перейти к спорной фразе в аудио.
- Настраиваемые параметры и Python-интерфейс — возможность повторять один и тот же эксперимент; настройки и версии надо фиксировать.
- README отдельно напоминает, что результат transcribe — ленивый generator: вычисление начинается при переборе сегментов. Время вызова функции без перебора не является временем распознавания.

## Запуск
- Сложность: нужен специалист для первой настройки (редакционная оценка): Python-среда, фиксированные версии, модель и параметры; это библиотека, не готовый редактор.
- Среда: компьютер/сервер с поддерживаемыми Python и CTranslate2/PyAV пакетами; Windows/Linux либо совместимая CPU-среда. Совместимость конкретной машины и macOS wheel отдельно не проверена.
- Python>=3.9; requirements.txt: ctranslate2>=4.0,<5, huggingface_hub>=0.23, tokenizers>=0.13,<1, onnxruntime>=1.14,<2, av>=11, tqdm. Не устанавливались.
- Для первого пилота: multilingual small (не small.en), CPU int8, language=ru, task=transcribe, один поток обработки/одна запись; записать версии и параметры. GPU не требуется для такого сценария.
- Для актуального NVIDIA-пути README требует CUDA12 cuBLAS и cuDNN9. Старые комбинации нуждаются в соответствующих версиях CTranslate2; автоматически менять зависимости не планируем.
- Модель Systran/faster-whisper-small: карточка указывает MIT, конверсия openai/whisper-small, FP16-хранение; compute_type можно менять при загрузке. Полный аудит всех поставляемых файлов/бинарных зависимостей не выполнен.
- Код MIT: при распространении сохранять уведомления и отказ от гарантий. Исходные веса Whisper также MIT по README OpenAI; другие дообученные модели имеют собственные условия.
- Стоимость кода/выбранных весов: обязательный лицензионный платёж не заявлен. Платный API/аккаунт/хостинг для локального пилота не нужны. Нужны загрузка весов и место под модель/пакеты/кеш, RAM, электричество и время специалиста/редактора. Точный объём и стоимость в рублях неизвестны до машины и замера; облачную аренду не выбирали.
- Не называем весь процесс бесплатным: существующее оборудование, трафик и ручная приёмка тоже ресурсы.

## Когда не подходит
Когда достаточно исходного сценария и ручного прослушивания; когда нет машины/времени для настройки; когда требуется гарантированная дословность без редактора. Модель может добавлять не произнесённые слова, особенно при тишине/неподходящем аудио. Музыка, шёпот, имена VITTORA и несколько голосов требуют отдельной проверки; распознавание не является достоверным назначением говорящих.
В issue #1476 сообщают о неверном языке при multilingual=True и предыдущем контексте. Не воспроизводили; первый пилот одноязычный с явным ru. PR #1680 описывает предложенное исправление восстановления временных меток после VAD; не считаем предложенный код принятым или проверенным нами.

## Первый пилот
- Вход: разрешённая копия 60 секунд чистой русской озвучки VITTORA, согласованный текст с 100 словами для ручного эталона, без музыки; исходник не менять.
- Ответственный: специалист VITTORA с редактором; в этом обзоре запуск не выполнен.
- Действие: подготовить изолированную среду только по отдельному решению, закрепить версии и multilingual small, CPU int8. Распознать с перебором всех segments, сохранить отдельный TXT и времена. Сравнить с исходным сценарием, вручную прослушать расхождения.
- Метрика: WER — сумма замен, пропусков и вставок, делённая на число слов эталона. Целевой редакционный порог <=10% на выбранных 100 словах; это критерий пилота, не результат/обещание.
- Дополнительно: вручную сверить 20 границ фраз, цель >=18/20 в пределах 0,3с; измерить wall-clock всего перебора, peak RAM и время ручной коррекции против текущего способа.
- Лимит: один материал, редакционный бюджет 30 минут первичного эксперимента, 0 расходов на API/аккаунты; реальные RAM/диск не определены. Если настройка не помещается, остановить и записать блокер.
- Откат: сохранить прежнюю ручную сверку, не перезаписывать исходную озвучку/текст; результаты только в отдельной папке.

## Кому ещё полезно
Авторам интервью, подкастов и учебных записей, которым нужен черновой текст с привязкой к аудио.
