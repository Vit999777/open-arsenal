## Что делает
Нарезает звук по времени, соединяет части и накладывает конец одного отрезка на начало следующего. Такое перекрытие с изменением громкости делает переход плавным; нужно прослушать, подходит ли он выбранной музыке.

## Польза для VITTORA
Предполагаемый сценарий: взять разрешённую копию «Воли», записать три диапазона в сценарии Python, собрать короткий тизер с двумя переходами и повторить его с теми же настройками. Это кандидат для аудиоподготовки, не для генерации музыки, видео или синхронизации губ. Конкретный исходный файл/таймкоды не получены; пилот не проводился. Качество, экономия времени, охват и доход не измерены.

Базовая линия сравнения — сборка теми же командами FFmpeg и ручная проверка стыков. Точный текущий сценарий, версии и время редактора нужно получить перед пилотом. Ранее опубликованный обзор Audacity не доказывает его внедрения. Замена рабочего процесса не выполнена.

## Главное преимущество
Для короткой аудиосборки операции нарезки, append(crossfade=...), fade_in/out представлены короткими выражениями Python, с временем в миллисекундах. По сравнению с ручной записью сложной цепочки фильтров FFmpeg можно хранить границы и параметры рядом с названиями фрагментов. Это редакционная оценка читаемости по README/API, не доказанное ускорение.

По сравнению с MoviePy для этой задачи не нужны видеообъекты и зависимости работы с изображениями; по сравнению с ffmpeg-python — есть высокоуровневый аудиообъект с операциями над отрезками. Вариант для коротких WAV может обходиться без внешнего FFmpeg по README, но импорт/запуск в выбранной среде ещё не проверен.

## Плюсы
- Явные времена нарезки в миллисекундах → параметры трёх отрезков можно записать и проверить, не полагаясь только на ручное выделение.
- Настраиваемое перекрытие → повторяемая длина каждого перехода. Музыкальная уместность требует прослушивания.
- AudioSegment неизменяем → операции возвращают новые объекты, исходный объект можно оставить для сравнения. Это не защита исходного файла: экспорт в тот же путь может его перезаписать, поэтому выводить только в отдельную папку.

## Запуск
- Сложность: потребуется специалист. Редакционная оценка: окружение Python, пути файлов, единицы времени, правила экспорта и контроль результата нужно задать явно.
- Среда: локальный CPU-компьютер. README содержит инструкции для macOS/Linux/Windows. Конкретная ОС и машина VITTORA не проверены; минимальные RAM/CPU/диск не установлены.
- Для первого эксперимента запланировать отдельное окружение Python 3.12, закреплённую версию Pydub 0.25.1 и доверенный PCM WAV. Это план, не проверенная совместимость и не команда к установке.
- WAV ввод/вывод по README не требует внешнего конвертера; MP3 и многие прочие форматы требуют FFmpeg/libav, воспроизведение — отдельно simpleaudio/PyAudio/ffplay/avplay. Для приёмки можно слушать файл обычным редактором; проигрыватель внутри Pydub не нужен.
- GPU, обученные веса, облако и внешний платный API в выбранном сценарии не обязательны. Обработка распакованного аудио и создание новых объектов требуют памяти; потребление измерить, длинные исходники не загружать без оценки.
- Полная стоимость: лицензионная плата за Pydub 0; обязательные API/модели/хостинг — отсутствуют в выбранном локальном WAV-сценарии. Компьютер, хранение, трафик установки, электричество, подготовка среды, прослушивание/правки и поддержка — реальные статьи затрат. RAM, диск, время и сумма в рублях неизвестны; ничего не покупалось.
- Лицензия Pydub MIT: сохранять copyright/условия при распространении, без гарантий. Для FFmpeg условия конкретной сборки, кодеков и зависимостей проверять отдельно; лицензия оболочки их не заменяет. Для музыки использовать только разрешённый материал. Полного аудита зависимостей и безопасности не было.

## Когда не подходит
Чистовой мастеринг, шумоподавление, коррекция тембра/интонации, синхронизация губ. Длинные записи без замера памяти. Чужие/сетевые/недоверенные плейлисты и файлы не включать в пилот. Переходы могут сдвигать музыкальный акцент, создавать наложение двух голосов и перегруз; нужна ручная приёмка.

## Первый пилот
- Вход: разрешённая копия PCM WAV «Воли»; конкретный путь/права/таймкоды ещё проверить.
- Ответственные: специалист готовит среду и сборку, редактор VITTORA принимает звук.
- Действие: отдельно подготовить три отрезка по 10 секунд с одинаковыми частотой/каналами/разрядностью; соединить с двумя перекрытиями по 1000мс. Первый результат только WAV, без MP3, изменения громкости и перезаписи мастера. Сохранить времена, версии и настройки.
- Метрические цели редакции, не результаты: длительность 10+10+10−1−1=28 секунд с ошибкой <=1мс; формат совпадает с выбранным входом; 2/2 стыка без слышимых щелчков/неприемлемого наложения и нового клиппинга. Если музыка не подходит к перекрытию — отклонить его независимо от точной длины.
- Повторить сборку с теми же настройками и сравнить SHA-256 распакованных PCM-данных (не контейнеров с метаданными). Записать peakRAM, wall-clock и время редакторской коррекции; сравнить с такой же сборкой FFmpeg. Ускорение заранее не обещается.
- Лимит: три входных отрезка/одна сборка/один повтор. Денежный и аппаратный лимиты пока не определены; расширение — после замера, без покупок.
- Откат: мастер и базовый сценарий не менять, выход в отдельной папке; при сбое оставить текущую сборку FFmpeg.
