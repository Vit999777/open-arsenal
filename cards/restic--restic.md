# restic — восстановление исходников VITTORA из резервной копии

- Исходный проект: https://github.com/restic/restic
- Направление VITTORA: надёжность
- Дата проверки: 2026-10-31
- Степень проверки: documentation — изучены источники, установка и пилот не выполнены.
- Статус: reviewing; публикация blocked, архив PNG не подтверждён.

## Что делает
Создаёт зашифрованные версии выбранных папок. Позволяет вернуть выбранную версию и отдельно прочитать данные архива для проверки целостности.

## Польза для VITTORA
Рассматриваем папку исходников сериала: сценарий, WAV диалогов, кадры, монтажный проект. Сейчас используются отдельные загрузки на разрешённые диски; факт загрузки не доказывает восстановление. Предполагаемый сценарий с restic: сохранить снимок, восстановить в пустую папку, сверить содержимое. Внедрение и сохранность материалов этим обзором не подтверждены.

## Главное преимущество
По сравнению с ручной загрузкой отдельных файлов — единая версия дерева файлов и штатная проверка данных. README и doc/045_working_with_repos.rst описывают snapshots, дедупликацию и check --read-data. Это сравнение возможностей, не измеренная экономия. По сравнению с Kopia нет преимущества в удобстве для новичка: у Kopia есть графический интерфейс. restic выбран как небольшой пилот управляемого командного процесса, а не как доказанно лучший продукт.

## Плюсы
- Версии папок → можно выбрать состояние до правки; не заменяет согласованную копию работающей базы.
- Повторяющиеся блоки не записываются заново → потенциально меньше повторного хранения; для уже сжатых видео эффект неизвестен.
- Шифрование и check --read-data → закрытый архив и отдельная проверка чтением всех данных; проверка не равна восстановлению.
- Windows/macOS/Linux и готовые бинарные файлы → не обязательно собирать исходники.

## Запуск
- Сложность: потребуется настройка; редакционная оценка. Нужно выбрать хранилище, сохранять пароль отдельно, проверять коды завершения, исключения и восстановление.
- Среда: поддерживаемый компьютер/сервер, процессор и RAM под объём архива, место для источников, репозитория, кеша и восстановления. GPU и модели не нужны. Точные RAM/CPU и время не измерены.
- Готовые бинарные файлы: сверить SHA256SUMS и подпись по официальной инструкции. Ничего не устанавливали. В master сборка требует Go>=1.26, go.mod toolchain go1.26.9; требования master не приписываются релизу.
- Расходы: код BSD-2-Clause без лицензионной платы. Моделей и обязательного платного API нет. Компьютер, диск, электричество, сеть, работа оператора и отдельное хранение пароля нужны; облачные объём/операции/скачивание оплачиваются по выбранному провайдеру. Полная сумма неизвестна до выбора объёма и места; нулевую стоимость не заявляем. Локальный пилот не требует новой подписки, если место уже есть.
- Лицензия: BSD-2-Clause, сохранять copyright, условия и disclaimer при распространении. Зависимости go.mod имеют свои лицензии, полный аудит не выполнен.

## Когда не подходит
- Нет доступной локальной копии исходников. Нативные Google Docs/Sheets нужно сначала экспортировать; поддержка Google Cloud Storage не означает прямой доступ к Google Drive.
- Утрачен пароль: README прямо предупреждает о потере доступа.
- Нужна одна понятная загрузка файла без настройки: текущий ручной процесс проще.
- Репозиторий на том же диске не защищает от отказа диска. Сжатие видео не гарантирует заметной дедупликации.
- Обычный check проверяет структуру, а не все данные: требуется --read-data и отдельное восстановление.
- Для живых баз/облачного состояния нужен согласованный экспорт. Интеграция с существующими дисками VITTORA не настроена.

## Первый пилот
- Вход: 10 доступных разрешённых файлов одного тестового эпизода (до 100 МиБ), без секретов/персональных данных. Если исходников нет — статус пилота blocked, не заменять чужим видео.
- Ответственный: оператор резервного контура, пока не назначен.
- Действие после отдельного разрешения на установку: закрепить версию/проверить дистрибутив; снять SHA-256/размеры; backup в отдельный тестовый репозиторий; check --read-data; restore в пустую изолированную папку; сравнить имена/размеры/SHA-256, открыть документ, декодировать аудио/видео и проверить CRC архивов, если они есть.
- Метрика: 10/10 файлов совпадают по именам, размерам и SHA-256; check без ошибок; нужные файлы открываются, CRC/декодирование без ошибок. Зафиксировать время backup/restore, прирост места и пиковую RAM. Это критерий редакции, не результат.
- Лимит: 60 минут, до 100 МиБ источника, 1 ГиБ свободного места для эксперимента; 0 новых платных услуг. Наличие такого места на будущей машине ещё не проверено.
- Откат: остановить пилот, продолжить ручное копирование; источники и старые копии не удалять, production не менять. Проверенным резервом считать только после полного восстановления.
- Результат: пилот не запускался.

## Кому ещё полезно
Авторам, монтажёрам, небольшим студиям с меняющимися исходниками и потребностью возвращать предыдущие версии.
