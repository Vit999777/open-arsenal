# Calibre — проверить электронную книгу перед выпуском

- Исходный проект: https://github.com/kovidgoyal/calibre
- Направление VITTORA: книга и аудио (book_audio).
- Дата проверки: 2026-10-28.
- Степень: documentation. Установка и пилот не выполнялись. Каталог reviewing.
- Выбран плановый слот 28.10, 18:00; утренний Pandoc /8 не повторяется.

## Что делает
Calibre управляет библиотекой электронных книг, конвертирует форматы и содержит редактор. В редакторе можно проверить внутренние ссылки и структуру EPUB, увидеть правки и вернуться к прежнему состоянию.

## Польза для VITTORA
Сценарий: копия EPUB одной главы «Архитектуры человека» → список проблем → ручная правка → просмотр в читалке перед загрузкой на площадку. Это следующий этап после предложенной утром сборки Pandoc, а не доказательство её выполнения. Подтверждены финальный PDF и сайт; наличие доступного EPUB или редактируемого исходника в этом запуске не установлено. Финальный PDF, опубликованные книги и сайт не менять.

## Главное преимущество
Перед отдельным ручным поиском по файлам EPUB — связка «проверка → переход к месту ошибки → правка → предпросмотр → откат» в одном интерфейсе, подтверждена руководством edit.html. Сравнение относится к наличию функций, а не к измеренной скорости/качеству. Предпросмотр в Calibre не заменяет реальную читалку. Принятие книжной площадкой не гарантировано.

## Плюсы
- Check book находит отсутствующие внутренние файлы/ссылки, некорректные HTML/CSS и ряд проблем OPF → можно составить список исправлений до отправки книги.
- Live preview обновляет отображение при правках → редактор видит влияние оформления.
- Checkpoints сохраняют состояния и позволяют сравнить/откатить изменения → обратимость пакетных правок.
- Выбранные функции работают локально → для проверки EPUB не нужен внешний API или отправка текста сервису. Интернетные функции метаданных/озвучки/новостей в пилот не включены.

Текущий процесс VITTORA: готовый PDF/сайт и предложенный общий исходник Pandoc. Подтверждённого этапа приёмки EPUB пока нет. Предлагается добавить проверку тестовой копии, не перестраивать существующие публикации.

## Запуск
- Сложность: потребуется настройка — редакционная оценка. Базовая проверка доступна через меню, но исправления HTML/CSS (разметки и оформления) требуют понимания структуры книги.
- Первый шаг после подготовки среды: добавить копию EPUB, правой кнопкой «Edit book», затем Tools → Check book. Сохранить исходный отчёт и создать checkpoint до правок. Автоматическое исправление всех ошибок не запускать.
- ОС Calibre 9.17: Windows 10 1809+ (64-bit), macOS 14+, Linux 64-bit Intel/ARM; Linux GLIBC ≥2.34 и libstdc++.so.6.0.30+, также возможны требования Qt/X11/OpenGL. Источники — официальные страницы загрузки. Совместимость конкретного компьютера не проверена.
- Sigil: README main указывает Windows x64 10 1809+, Qt ≥6.4 для сборки; релиз 2.8.1 Linux AppImage нацелен на glibc ≥2.35. Требования main и релиза не смешиваются; точная совместимость Mac/машины не проверена.
- EPUBCheck: pom.xml v5.4.0 задаёт Java source/target 1.8. Wiki Running содержит старые примеры v4.0.2, поэтому её старые минимумы Java не используем как подтверждение для v5.4.0. Нужен совместимый Java runtime, его проверка впереди.
- Модели/GPU: для выбранного редакторского сценария не требуются.
- Полная стоимость: код без лицензионной платы; веса отсутствуют; API/хостинг не нужны в локальном сценарии; свой компьютер, диск, электричество и труд — затраты, фактические RAM/время/сумма неизвестны. Платные подписки/аккаунты не создавались; лимит новых расходов пилота 0 ₽. Озвучка, новости и скачивание внешних ресурсов не входят.
- Лицензия: GPLv3, LICENSE репозитория; условия распространяемой программы/модификаций соблюдать. Лицензия редактора не выдаёт права на книгу, изображения или шрифты. У зависимостей свои условия; полного аудита нет. Sigil GPLv3, EPUBCheck BSD-3-Clause (сохранение notices, без использования имён правообладателей для одобрения).

## Когда не подходит
Не гарантирует приём площадкой, отсутствие литературных ошибок, идентичность печатному PDF или корректность на всех устройствах. Предпросмотр не показывает некоторые поля/разрывы страниц/варианты встроенных шрифтов. Автоисправление HTML может дать неожиданный результат — предупреждение руководства. Для формальной проверки спецификации полезен отдельный EPUBCheck; для точной печатной вёрстки нужен другой этап. Если нет EPUB/исходника, сначала получить законную редактируемую копию; не обещать восстановление книги из PDF.

## Первый пилот
- Вход: копия EPUB одной разрешённой главы VITTORA; доступный файл ещё не выбран. Зафиксировать SHA-256 и версию программы. Не конвертировать финальный PDF вслепую.
- Ответственный: редактор VITTORA; конкретные исполнитель/машина пока не назначены.
- Действие: Check book → сохранить список → вручную исправить одну подтверждённую проблему → сравнить → открыть в отдельной читалке.
- Метрика (редакционный порог): 10/10 заранее выбранных элементов (заголовки, цитаты, сноски, оглавление/переходы, кириллица) сохранены; 0 новых битых внутренних ссылок; все оставшиеся предупреждения разобраны письменно. Измерить минуты правок, RAM и размер файлов. Результатов ещё нет.
- Лимит: одна глава, до 45 минут, 0 ₽ новых услуг. Расход RAM/диска заранее проверить, числовой лимит не определён.
- Откат: отдельная рабочая папка, исходный EPUB/PDF не перезаписывать; checkpoint плюс нетронутая копия. Выпуск и загрузки на площадки не входят в пилот.

## Кому ещё полезно
Авторам, редакторам и владельцам небольших издательств, которые готовят электронные книги и хотят видеть конкретное место ошибки.
