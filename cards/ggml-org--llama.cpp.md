# llama.cpp — теги для текстов на своём компьютере

- Исходный проект: https://github.com/ggml-org/llama.cpp
- Направление VITTORA: агенты / RAG; ближайший вечерний слот 29.10.2026, продолжение темы локального контура после Qdrant. Следующее направление по плану — сайт/журнал.
- Дата проверки: 2026-10-29.
- Степень проверки: documentation — изучена документация, LICENSE, сборка, релиз и выборка issues/PR. Не установлен, материалы VITTORA не запускались. Статус reviewing.
- Публикация обзора не означает внедрения.

## Что делает
Запускает языковые модели на своём компьютере. Сам движок не содержит модель и не является готовой базой знаний, редактором, озвучкой VASKO или системой публикации.

## Польза для VITTORA
Сценарий: десять разрешённых статей/коротких фрагментов книги → до трёх тегов из фиксированного редакционного словаря и название рубрики → ручная приёмка → тестовый каталог. Предлагаемая структура сокращает число произвольных форматов, но экономия времени и точность не измерены. Текущая точка сравнения — ручная разметка/проверка редактором, доступный облачный помощник; реально работающий автоматический теггер VITTORA не подтверждён.

## Главное преимущество
Для узкого локального обработчика можно напрямую задать модель, параметры и схему ответа без дополнительного слоя управления. Основание: README описывает C/C++, CPU/GPU и локальный сервер; grammars/README.md — ограничение формата ответа. Это сравнение состава и возможностей, не скорости или качества.

| Кандидат | Подтверждено в первоисточниках | Почему выбран / отложен |
|---|---|---|
| llama.cpp | MIT, CPU/GPU, готовые бинарники или CMake, сервер, схемы ответа | Основной кандидат для контролируемого локального пилота; потребует выбора модели |
| Ollama | MIT, пакеты для Windows/macOS/Linux, каталог моделей, локальный/облачный режим, API; README указывает llama.cpp backend | Альтернатива для более удобного управления моделями; удобство — редакционная оценка, не замер. Нужно явно выбрать локальный режим |
| LocalAI | MIT, CPU-only контейнер и отдельные backends, API нескольких провайдеров, мультимодальность, пользовательские роли | Более широкий серверный контур, чем нужно для 10 текстов; расходы на контейнеры/веса/хранение зависят от выбранного backend |

У всех лицензия движка не заменяет лицензию модели и зависимостей. Нельзя объявлять любой из вариантов бесплатным по полной стоимости.

## Плюсы
- Локальная обработка после подготовки модели → текст можно держать на своей машине. Сеть нужна для первоначального получения бинарников/весов; удалённые подключения в пилоте не нужны.
- Работа на CPU → GPU не обязателен; скорость и достаточность конкретного компьютера неизвестны.
- Ограничение вывода грамматикой/подмножеством JSON Schema → возможность получать теги в структуре для каталога. Это не проверяет смысл, не гарантирует факты и не поддерживает произвольную схему полностью.

## Запуск
- Сложность: потребуется настройка (редакционная оценка): выбрать подходящую русскоязычную модель, проверить права на веса, выбрать готовый бинарник под ОС или собрать, задать схему и измерить ресурсы.
- Среда: Windows, macOS, Linux, локальный компьютер; CPU либо поддерживаемый GPU/backend. Для сборки — C/C++ toolchain и CMake, корневой CMakeLists.txt указывает минимум 3.14; Windows build guide описывает VS2022.
- Первый практический запуск после выбора модели: готовый официальный релиз, локальный GGUF-файл, CLI или сервер только на loopback. README сейчас использует команды `llama cli` / `llama serve`; параметры и имена бинарников сверить с закреплённым релизом. Команды здесь не исполнялись.
- Память: размер весов + память контекста и рабочие буферы. Универсального RAM/VRAM минимума для всех моделей нет; модель, размер/квантование и машина не выбраны.
- Расходы: код — 0 лицензионной платы MIT; веса/лицензия — пока неизвестны; обязательный платный API или облачный хостинг в локальном сценарии отсутствует; компьютер, диск, электричество, трафик, настройка и редакторская проверка стоят ресурсов. Полный бюджет и длительность неизвестны, никаких покупок/регистраций не выполнено.
- Лицензия кода MIT: при распространении сохранить copyright и текст разрешения. Модели и зависимости отдельно; полного юридического/безопасностного аудита нет.

- Проверен release/latest: v0.8.0 от 28.10.2026; ночные сборки и master могут отличаться. Релизные заметки не доказывают работоспособность на нашей машине.
- Изучен открытый issue #31328: автор сообщает HTTP 500 для response_format на LFM3 при конкретных настройках, PR #31374 предлагает исправление. Не воспроизведено нами, не распространяем вывод на все модели; выбранную комбинацию версии/модели/схемы проверить.
- Ollama latest v0.40.13 от 28.10.2026: исправления/добавления для LFM3; выборка включает issue #19390 о мультимодальности и PR #19389/#19387 о преобразовании формата API. PR — предложение изменения, не выпущенная гарантия.
- LocalAI latest v4.12.1 от 23.10.2026: security fix политики внешних URL. Выборка PR #12959/#12958/#12957 касается ответа при отключённом thinking, audio/backend и tool_choice. Результаты авторов не наши тесты.
- Два предполагаемых пути документации требований LocalAI вернули ошибку чтения; требования контейнерного запуска и CPU/GPU прочитаны непосредственно в README, полный перечень для конкретной модели не установлен.
- Не подходит как обещанная замена облачного помощника на всех задачах; для редких тегов ручной процесс может быть проще. Не подходит без совместимой модели/памяти или при ожидании гарантированно верной семантики.
- Нельзя подключать автономную отправку постов, выполнение команд или менять production по факту этого обзора.

## Первый пилот
- Ответственный: редактор VITTORA совместно с техническим исполнителем; конкретный исполнитель и компьютер ещё не назначены.
- Вход: 10 разрешённых коротких текстов, фиксированный словарь тегов, заранее согласованная ручная разметка; оригиналы не менять.
- После проверки лицензии/размера модели закрепить релиз, SHA-256 весов, параметры/схему, прогнать локальную копию.
- Метрика, выбранная редакцией: валидный формат 10/10, допустимые теги только из словаря 10/10, смысловое совпадение с ручной разметкой минимум 8/10 материалов. Записать долю исправлений, время первого/повторного запроса, пик RAM/VRAM и размер диска. Сравнить с ручным процессом; пока результатов нет.
- Лимит: 60 минут исследования пилота, 0 ₽ новых услуг/оборудования. Это плановый потолок, не оценка достаточного времени. Если ресурсов не хватает — остановка без покупки.
- Откат: закрыть локальный процесс, оставить результаты в тестовой папке; рабочий каталог и исходники не меняются.
