# Audacity — подготовка фрагментов треков VITTORA

- Исходный проект: https://github.com/audacity/audacity
- Направление VITTORA: музыка.
- Дата проверки: 2026-10-26.
- Степень проверки: документация (documentation). Установки, прослушивания и медиа-пилота не было.
- Версия для рассмотрения: Audacity 4.0.1, стабильный релиз GitHub от 30.09.2026; официальный сайт также указывает 4.0.1.
- Каталог: reviewing; выпуск blocked, не опубликован.

## Что делает
Audacity — редактор звука на компьютере. Позволяет работать с несколькими дорожками, выбирать фрагменты записи и экспортировать их отдельными файлами.

## Польза для VITTORA
Сценарий: открыть копию утверждённого трека «Воля», отметить три разных начала будущего тизера и получить три 18-секундных WAV-фрагмента для сравнения на слух. Это план, а не выполненная обработка. Для «Хочется жить» редактор сам не исправит устаревшее звучание аранжировки или вокала.

Текущий процесс: музыка создаётся в Suno, озвучка — ElevenLabs, видео собирается в HyperFrames. Audacity рассматриваем как ручной этап отбора аудио между исходником и монтажом. Он не заменяет генерацию музыки, не создаёт автоматически хороший хук и не гарантирует принятия дистрибьютором.

## Главное преимущество
Перед простым обрезанием файла командой FFmpeg — визуальная работа с несколькими фрагментами и именованными областями в одной сессии. В [релизе 4.0.1](https://github.com/audacity/audacity/releases/tag/Audacity-4.0.1) прямо указан экспорт отдельных дорожек или размеченных областей в отдельные файлы. Это подтверждённая возможность интерфейса, а не доказанная экономия времени или лучший звук.

## Плюсы
- Несколько дорожек и редактирование клипов → можно разместить варианты тизера рядом для ручного выбора ([README](https://github.com/audacity/audacity/blob/master/README.md), [релиз 4.0](https://github.com/audacity/audacity/releases/tag/Audacity-4.0.0)).
- Экспорт размеченных областей отдельными файлами → можно подготовить несколько кандидатов начала для одного трека (релиз 4.0.1).
- Локальная работа с проектом → в плановом пилоте исходник не нужно отправлять в дополнительный облачный сервис. Облачное сохранение и сторонние плагины в пилот не входят.

Не отклонён по качеству |
| [Ardour](https://github.com/Ardour/ardour) | README/COPYING/README-GITHUB, официальный сайт, требования и условия скачивания; запись/монтаж/сведение, MIDI, OSC | Рассматривать для сложных музыкальных сессий; для трёх фрагментов требует дополнительной настройки. Сравнительного запуска нет |

Tenacity: README разрешает GPLv2 или позднее; LICENSE отмечает отдельные условия библиотек/документации, BUILDING включает GPL3 по умолчанию. Нельзя приписывать любой сборке только GPLv2 без проверки состава. Для сборки нужны CMake >=3.25, C++17, wxWidgets и другие библиотеки; для Windows зависимостей указан объём 10 GB — это размер сборочного окружения, не минимум для обычного запуска. Внешний релиз/трекер Codeberg недоступны этому чтению (robots/restricted). Пустые GitHub releases/issues не означают отсутствие выпусков/ошибок.

Ardour: COPYING описывает GPLv2 или позднее и отдельные условия плагинов. Официальные готовые сборки могут требовать оплату, самостоятельная сборка сложна; конкретная цена здесь не подтверждена. Официальные требования рекомендуют 2 GB RAM, 64-битную машину и дополнительный диск для записей; нагрузка зависит от обработки. GitHub release tarballs прямо не поддерживаются по README-GITHUB. GitHub releases/issues пусты; внешний трекер при чтении недоступен. Официальная главная сообщает о 9.8; полного разбора заметок этого релиза нет.

## Запуск
- Сложность: потребуется небольшая ручная настройка. Это редакционная оценка: нужно выбрать аудиоустройство, частоту дискретизации, области и формат экспорта.
- Среда: настольный компьютер Windows/macOS/GNU/Linux; у официальной страницы загрузок есть Windows x86_64/ARM64, универсальная macOS и Linux AppImage x86_64/ARM64. Подходящая версия ОС и точные ресурсы компьютера VITTORA не подтверждены.
- Не путать сборку с запуском: BUILDING тега 4.0.1 требует Git/CMake/Ninja/C++/Qt 6.10 и зависимости; в текущем master уже указан Qt 6.11. Это не основание требовать Qt от пользователя готового установщика. При пилоте закрепить готовую 4.0.1 и проверить её совместимость.
- Код/основное приложение: без обязательной покупки для выбранного локального сценария. Лицензия GPLv3.
- Модели и внешний AI API: не требуются. Suno/ElevenLabs остаются отдельными ранее оплаченными источниками, их расходы не становятся расходами Audacity.
- Плагины и облако: необязательны, их стоимость и условия не включены и не проверены; не покупать для пилота.
- Полная стоимость: компьютер + электричество/вычисления + диск для исходника/проекта/трёх экспортов + резервная копия + время оператора/сопровождения. Фактические RAM, размер проекта, время и денежный итог неизвестны. GPU для простого аудиоредактирования не заявлен обязательным; конкретная нагрузка не измерена.

## Ограничения и автоматизация
В примечаниях 4.0 перечислены отсутствующие функции: Macro Manager и scripting pipe — управление через сценарии. В прочитанных заметках 4.0.1 возврат этих функций не заявлен; их наличие в рабочей 4.0.1 не проверено. Поэтому этот разбор не рекомендует её как готовый автоматический звуковой backend для агентов VITTORA.

В 4.0 новый формат .aup4: .aup3 конвертируется, обратное сохранение в .aup3 не поддерживается. Сначала делать копии. В 4.0.1 перечислены исправления повреждения проекта после неудачного сохранения и конвертации .aup3; это отчёт разработчиков, не наш тест безопасности.

[Issue 12591](https://github.com/audacity/audacity/issues/12591): сообщение о незакрывающемся стартовом окне при импорте двух файлов на macOS 4.0.1. [Issue 11424](https://github.com/audacity/audacity/issues/11424): отображение сочетания Preferences в настройках. Нами не воспроизведены; выборка не является полным аудитом ошибок.

## Когда не подходит
Для полностью автономной цепочки агентов без оператора; для исправления самой композиции, исполнения и аранжировки; для заявления о профессиональном мастеринге без прослушивания и измерений. Уже утверждённый мастер не следует повторно обрабатывать ради самого факта использования редактора.

## Первый пилот
- Ответственный: музыкальный редактор VITTORA; конкретный исполнитель не назначен.
- Вход: копия утверждённой «Воли», предпочтительно исходный WAV; если доступен только сжатый файл, записать это ограничение.
- Действие: подготовить три размеченные области по 18 секунд, экспортировать WAV без изменения оригинала; открыть файлы снова и сравнить с обрезкой в текущем процессе.
- Критерии: 3 читаемых файла; длительность каждого 18 ±0,05 с; сохранены исходные частота дискретизации и число каналов; нет новых цифровых перегрузок и слышимых щелчков на границах при ручном сравнении.
- Метрики: время ручной подготовки, число правок границ/экспорта, пиковый уровень до/после, размер файлов, пик RAM. Техническую измерительную процедуру и инструмент измерения согласовать до пилота; это целевые критерии, не результаты.
- Плановый лимит: один трек/три фрагмента, до 30 минут работы, без платных плагинов/API. Вычислительный лимит ещё не подтверждён.
- Откат: удалить только тестовые проект/экспорты, оставить исходник и существующий монтаж неизменными.

## Кому ещё полезно
Музыкантам, авторам подкастов и видеоредакторам, которым нужен ручной отбор и подготовка коротких аудиофрагментов.
