# Ragas — проверка поиска отрывков VITTORA

- Проект: https://github.com/vibrantlabsai/ragas
- Направление: агенты и база знаний
- Дата: 2026-11-09
- Степень проверки: документация, манифест, лицензия, релиз, код метрики и выборка обсуждений. Запуск и пилот предстоят.

## Что делает

Сравнивает найденные отрывки с эталоном и считает долю найденных нужных отрывков.

## Польза для VITTORA

Сохранить стабильные ID отрывков и сравнивать выдачу двух настроек поиска с эталоном редактора.

## Главное преимущество

Ручной подсчёт редактора или несколько строк Python достаточны для разовой проверки. Ragas даёт именованную метрику для повторных прогонов и возможность отдельно добавить другие оценки. Haystack DocumentRecallEvaluator удобен, если выдача уже представлена объектами Haystack. DeepEval подходит, когда нужны тесты ответов, его Contextual Recall использует модель-оценщик. Текущий рабочий процесс оценки VITTORA не подтверждён, ручная сверка — контроль пилота.

## Плюсы

- Формула по ID даёт повторяемый результат при одинаковом вводе. [Код v0.4.3](https://github.com/vibrantlabsai/ragas/blob/v0.4.3/src/ragas/metrics/_context_recall.py)
- Сравнение выполняется без модели-оценщика. Разметку можно держать локально. [Описание метрики](https://docs.ragas.io/en/v0.4.3/concepts/metrics/available_metrics/context_recall/)

## Запуск

Сложность средняя. Нужно согласовать ID отрывков и собрать эталон редактора.

Python ≥3.9 по манифесту v0.4.3, изолированная среда и совместимые зависимости. Для IDBasedContextRecall модель, GPU, платный API, аккаунт и хостинг не требуются. Код Apache-2.0 без лицензионной платы. Полная стоимость — время редактора на эталон и разработчика на стабильные ID и адаптер, локальные вычисления, хранение набора и поддержка. Денежная сумма и расход RAM неизвестны. При подключении оценки ответов через модель дополнительно учитывать её лицензию, токены или локальное оборудование.

Apache-2.0 основного кода. При распространении соблюдать LICENSE и применимые уведомления. Условия зависимостей и отдельно выбранных моделей не проверены.

## Когда не подходит

Нужны сопоставимые ID и непустой эталон. При пустом эталоне код возвращает NaN. Метрика не проверяет верность ответа, цитат и порядок внутри переданного списка. При изменении нарезки отрывков нужно обновить эталон либо сопоставление ID.

## Первый пилот

Взять 30 разрешённых отрывков и 10 вопросов с отмеченными редактором ID. Зафиксировать первые пять результатов поиска по словам и поиска с фильтром актуальной версии. Сравнить расчёт Ragas и ручной контроль. Лимит 90 минут после подготовки среды и эталона, без покупок. Ответственные: редактор и разработчик поиска, имена не назначены. Откат — оставить ручную сверку и не менять поиск.

Совпадение автоматического и ручного recall@5 в 20/20 измерениях, по 10 вопросов на настройку. Замерить длительность и RAM; отдельно посчитать случаи пустого эталона. Пилот не проводился.

## Кому ещё полезно

Командам, которые обновляют поиск по справкам, статьям или учебным материалам.
