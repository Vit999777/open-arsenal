# librosa — ориентиры ритма для монтажа тизера

- Исходный проект: https://github.com/librosa/librosa
- Направление VITTORA: музыка (music), передача отметок в видеомонтаж.
- Дата проверки: 2026-10-27.
- Степень проверки: documentation. Прочитаны первоисточники; установка, анализ аудио и медиа-пилот не выполнялись.
- Рассматриваемая версия: 1.0.0, релиз 11.08.2026. Не архивирован; pushed_at 06.10.2026 по GitHub.
- Редакционная карточка остаётся reviewing: фактическая осуществимость на рабочем компьютере и полная стоимость не измерены.

## Что делает
librosa — библиотека Python для анализа аудио. Функция beat_track оценивает темп и возвращает предполагаемые моменты ударов, в том числе в секундах. Это программный компонент, а не готовый видеоредактор.

## Польза для VITTORA
Задача: подготовить проверяемые ориентиры для смены кадров в музыкальном тизере. Предлагаемый пример — 30 секунд копии «Воли»: получить таблицу отметок, сверить её на слух и передать принятые точки монтажёру. Мастер не менять. До пилота это сценарий применения, не полученный результат.

Текущий подход — выбор точек монтажёром по слуху и форме волны; измеренного базового времени нет. Утром опубликован обзор Audacity для ручной подготовки фрагментов, но его внедрение и контрольный результат также не подтверждены. librosa могла бы дополнить редактор числовыми отметками; заменой монтажа, мастеринга или Suno её не считаем.

## Главное преимущество
По сравнению с ручным поиском — машинно читаемые отметки в секундах и явные параметры повторения; это подтверждает документация функции beat_track. Это преимущество формата процесса, а не доказательство более точного или быстрого монтажа. По сравнению с aubio и Essentia — разрешительная ISC лицензия самого кода и достаточный для малого пилота Python-интерфейс; точность алгоритмов между собой не измерялась.

## Плюсы
- Выход в секундах → можно сохранить ориентиры в CSV; запись CSV и импорт в монтаж пока требуют отдельного сценария.
- Параметры частоты и шага анализа задаются явно → можно повторить опыт с зафиксированными входом и версиями.
- Для выбранного beat_track не нужны платный API или веса нейросети → можно работать с локальным WAV, не отправляя исходник внешнему генератору. Установка зависимостей требует получения пакетов.
- Код не меняет мастер сам по себе при чтении и анализе; будущий сценарий должен писать только отдельные файлы.

## Запуск
- Сложность: нужен специалист (редакционная оценка): необходимо подготовить Python-окружение, написать небольшой сценарий, сохранить таблицу и проверить привязку к аудио.
- Среда: локальный компьютер Windows/macOS/Linux с совместимыми Python и бинарными зависимостями; конкретные ОС/архитектуры рабочего места неизвестны. Поддержку Windows ARM64 нельзя считать подтверждённой по открытому PR.
- Версия 1.0.0: Python >=3.12; NumPy >=2.1, SciPy >=1.15, numba >=0.61, scikit-learn >=1.6, soundfile >=0.12.1, soxr >=1.0 и прочие зависимости из setup.cfg. Для построения картинок — отдельная matplotlib >=3.10.
- План запуска: отдельное окружение, закрепить librosa 1.0.0 и полный список зависимостей; загрузить локальный WAV, вызвать beat_track с units=time, экспортировать секунды. Команды установки не выполнялись.
- Оборудование: для выбранного анализа обязательная GPU не заявлена. Минимум RAM, место на диске, время первого/повторного прохода на целевой машине — неизвестны.
- Расходы: плата за код — 0; для beat_track веса моделей и API не требуются; облако/хостинг для локального пилота не нужны. Оборудование, интернет для пакетов, электричество, рабочее время настройки/сверки — реальные статьи, суммы неизвестны. Новые аккаунты и покупки не создавались.
- Лицензия librosa: ISC, разрешено использование/модификация/распространение с сохранением copyright и permission notice; гарантий нет. Лицензия кода не даёт права на музыку. Зависимости и декодеры имеют отдельные условия, полного аудита их лицензий не было.

## Когда не подходит
- Нужен готовый монтаж без Python или требуется выбрать лучший припев: список ударов этого не делает.
- Сложный ритм, тихое вступление, меняющийся темп: гипотезы нужно проверять на слух; правильные доли/акценты не гарантированы. Без заметных атак функция может вернуть 0 BPM и пустой список.
- Настройка моно/многоканальности и возврат массива темпа требуют аккуратной обработки; нельзя молча менять частоту дискретизации или путать кадры анализа с секундами.
- На Python <3.12 версия 1.0.0 не подходит без смены окружения; старую версию исследовать отдельно.
- Если ручная разметка одного ролика проще — оставляем текущий процесс.

## Первый пилот
- Ответственный: технический редактор VITTORA; исполнитель и рабочая машина ещё не назначены.
- Вход: разрешённая копия 30 секунд «Воли» с читаемым ритмом, WAV; права и версию файла подтвердить до запуска.
- Действие: вручную отметить 20 опорных ударов, получить автоматические отметки, сравнить без подгонки ручного эталона. Сохранить SHA-256 входа, версии, sr, hop_length, настройки и CSV.
- Успех (редакционный критерий, не результат): не менее 18 из 20 ручных точек имеют взаимно однозначное совпадение в пределах ±100 мс; отдельно указать лишние отметки, долю пропусков и ошибки двойного/половинного темпа.
- Измерить: время настройки отдельно, холодный/повторный проход, пиковую RAM, время ручной сверки и ручного базового варианта. Выигрыш не обещаем.
- Лимит: один локальный отрывок; 0 ₽ новых услуг, без аренды GPU и API. Числовой лимит RAM/времени согласовать после выбора машины, сейчас неизвестен.
- Откат: удалить/отложить только экспериментальные результаты обычным процессом после решения редактора; исходный мастер не менять. Вернуться к ручной разметке.
- Результат: пилот не выполнен.

## Кому ещё полезно
Монтажёрам музыкальных клипов, авторам рилсов и разработчикам аудиоаналитики, которым нужны проверяемые временные ориентиры.
