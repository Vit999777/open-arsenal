# OCRmyPDF — поиск по сканам к книге VITTORA

- [Исходный проект](https://github.com/ocrmypdf/OCRmyPDF)
- Направление VITTORA — книга и аудиокнига
- Проверка — 11.11.2026, документация 17.14.1 и локальный синтетический пример 16.7.0

## Что делает

Программа распознаёт печатные буквы на изображении страницы и добавляет в PDF текстовый слой, по которому можно искать.

## Польза для VITTORA

Находить цитаты и термины в разрешённых русскоязычных сканах к книге VITTORA, сохраняя готовые текстовые страницы смешанного PDF. Создать отдельную поисковую копию смешанного PDF с материалами к книге и проверять цитаты по исходному изображению.

## Главное преимущество

Исходная точка — изображение страницы, для которого контрольным способом служит поиск вручную и сверка цитаты со сканом. Используемый сейчас инструмент OCR VITTORA не подтверждён. Tesseract 5.5.4 сам выдаёт PDF из изображений, а для смешанного исходного PDF потребуются разбор страниц и последующая сборка. NAPS2 8.6.0 тоже умеет распознавать импортированный PDF с пропуском текстовых страниц и поддерживает графический интерфейс и CLI. Для воспроизводимой обработки смешанного файла выбрал OCRmyPDF за явно задаваемые режим, язык и тип выхода. Сравнение скорости и качества на русских сканах предстоит.

## Плюсы

- Режим skip обрабатывает страницы без готового текста. Это подходит для PDF, где сканы и цифровые страницы идут вперемешку. [Описание режимов](https://github.com/ocrmypdf/OCRmyPDF/blob/v17.14.1/docs/advanced.md)
- Локальный запуск и выбор языка позволяют оставить материалы на рабочем компьютере и применить русскую модель. [README](https://github.com/ocrmypdf/OCRmyPDF/blob/v17.14.1/README.md)

## Запуск

Сложность умеренная. Нужно подготовить движок распознавания, языковой пакет и средство чтения страниц PDF.

OCRmyPDF 17.14.1, Python ≥3.11, Tesseract ≥4.1.1 по README и установленная модель rus. Для растеризации — pypdfium2 или Ghostscript по инструкции, плюс fpdf2 и uharfbuzz в окружении. Для пилота выбран обычный PDF с pypdfium2. Среда — локальный Linux, macOS или Windows с совместимыми пакетами. Для базового CPU-сценария платный API, сервер и отдельная видеокарта не нужны. Учесть память, временные файлы и диск, электроэнергию, подготовку окружения и ручную сверку. Сумма и ресурсы на архивных сканах не измерены.

Основной код OCRmyPDF — MPL-2.0, Tesseract и данные tessdata — Apache-2.0. У pypdfium2, PDFium и Ghostscript свои лицензии, которые следует проверить для выбранной сборки и её распространения. Права на сами страницы оцениваются отдельно.

## Когда не подходит

Режим skip пропускает целую страницу при обнаружении текста. Скан с цифровым водяным знаком или номером на той же странице может остаться без распознавания. PDF/A, формы, подписи и логическая структура требуют отдельных проверок. Рукописи и сложные таблицы за пределами пилота. На повреждённых или неизвестных файлах использовать изолированную среду. Исходники хранить отдельно.

## Первый пилот

Взять копию 5 разрешённых страниц с печатной кириллицей и одну цифровую контрольную страницу. Отметить 10 фраз и страницы вручную. Выпустить обычный PDF с параметрами --mode skip -l rus --output-type pdf --optimize 0, затем проверить поиск и вид страниц. Контроль — исходный скан и ручная разметка. Лимит — 45 минут после подготовки зависимостей, без покупок. Ответственный — редактор, имя не назначено. Откат — пользоваться исходным PDF и ручным указателем.

Критерий успеха — минимум 9 из 10 фраз находятся на правильных страницах, цифровая страница сохраняет извлекаемый текст, все 6 страниц остаются в порядке и без обрезки. Записать длительность, пик ОЗУ и размер файла. Проверить SHA-256 исходника до и после.

## Кому ещё полезно

Редакторам и владельцам локальных архивов с печатными сканами, в которых нужен поиск по словам.
